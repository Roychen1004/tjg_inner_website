# 14 — 請款操作手冊

> 鐵正綱工程 內部管理系統
> 2026-08-02｜從零建一個案子的請款設定，到收到錢

這份是**照著做**的手冊，不是說明書。每一步都寫：點哪裡、填什麼、會看到什麼。

概念性的問題（里程碑跟請款事件差在哪）看 `../員工手冊.md` §5。

---

## 0. 先看懂一張圖

```
① 建期別        ② 建里程碑        ③ 建批次         ④ 現場簽收      ⑤ 會計收款
   （工程分期）     （抄合約條件）      （歸到期別）       （觸發請款）     （轉狀態）

專案頁            請款收款頁          追蹤看板          追蹤看板        請款收款頁
   │                  │                 │                │              │
   └── 第一期 ←───────┘綁定             │                │              │
        ↑                               │                │              │
        └───────────────────────────────┘歸屬            │              │
                                                          │              │
                                        簽收時系統：       │              │
                                        看這批屬於哪一期 ──┘              │
                                        找到綁那一期的里程碑              │
                                        評估條件達成沒 ────────────────→ 產生請款事件
```

**關鍵在②和③：批次不是直接綁到里程碑，是兩邊都綁到「期別」，靠期別對上。**

如果案子不分期，②③都跳過期別，里程碑直接看全案所有批次——一樣能跑。

## 1. 系統會告訴你還缺什麼

不用背上面那張圖。**請款收款頁選了專案之後，最上面有一塊「請款設定檢查」**：

```
⚠ 請款設定檢查
  還有 1 項必須處理                                    ▼

  ✔ 建立合約里程碑      已建立 4 筆：簽約訂金、第一期請款…
  ✔ 比例加總 100%      各期比例合計 100%
  ✔ 里程碑綁定期別      2 / 4 筆已綁定期別
  ⚠ 追蹤單元歸屬期別    有 2 個追蹤單元沒歸期別：樓梯鋼構、桁架B區
      ┌────────────────────────────────────────────┐
      │ ★ 批次不是直接綁到里程碑上的——兩邊都綁到期別，  │
      │ 靠期別對上。沒歸期別的批次簽收時，找不到對應的   │
      │ 里程碑，就不會觸發請款                        │
      └────────────────────────────────────────────┘
      該做的：編輯這些追蹤單元，選對應的期別 →
  ✘ 批次填寫總重量      3 / 5 個批次沒填總重量
      該做的：編輯這些批次填總重量 →
```

**每一項都寫了「現在怎樣、為什麼重要、該去哪裡做」，「該做的」是連結，點了直接過去。**

全部打勾就會變成 `✔ 請款自動化已就緒` 並自動收合。

專案頁展開任一案的「請款進度」區塊也看得到同一份檢查。

## 2. 實際走一遍：從零建一個分期的案子

### 步驟 1｜建專案

**專案頁 → 新增專案**

| 欄位 | 填什麼 |
|---|---|
| 案名 | 台中廠房鋼構 |
| 專案類型 | 鋼構 |
| 客戶 | 選一個（沒有就先到**設定 → 客戶**建） |
| 專案負責人 | 選一個（他才看得到這案的金額） |
| 合約金額 | `50000000` |

建好後系統給編號 `P-2026-006`，主線停在第一站「接案」。

---

### 步驟 2｜建期別（合約分期才需要）

**專案頁 → 展開這個案 → 期別 → 新增期別**

輸入 `第一期`，送出。再新增 `第二期`。順序自動遞增，不用管。

> **什麼時候需要期別？**
> 看合約。合約寫「第一期構件全數簽收後請款 40%」→ 需要。
> 合約寫「按實際交貨數量分批請領」→ 不需要，跳過這步。

---

### 步驟 3｜建里程碑（把合約抄進來）

**請款收款頁 → 選這個專案 → 合約里程碑分頁 → 新增里程碑**

假設合約寫：

```
一、簽約後 7 日內支付訂金 20%
二、第一期構件全數運抵工地並經業主簽收後，請領 40%
三、第二期累計交貨達 80% 得請領 30%
四、全案驗收合格後支付尾款 10%
```

四條就建四筆。以第二條為例：

| 欄位 | 填什麼 | 說明 |
|---|---|---|
| 順序 | `2` | 系統自動帶下一個可用號，重複會擋 |
| 名稱 | `第一期請款` | |
| 合約原文 | `第一期構件全數運抵工地並經業主簽收後，請領 40%` | 抄進來，日後對帳不用翻合約 |
| 比例 | `40` | 系統即時顯示：`5,000 萬 × 40% = 2,000 萬　｜　含這筆全案共 60%，還差 40%` |
| 觸發方式 | **該期全部簽收** | 見下表 |
| **適用期別** | **第一期** | ★ **這就是「綁定」** |
| 合約指定交貨地點 | 台中廠房工地 | 選填。簽收地點不符會警告但不擋 |

選了期別之後，**下面會立刻顯示這筆會看哪些批次**：

```
這筆會看 0 個追蹤單元（僅 第一期）
這個範圍還沒有追蹤單元。沒有批次就不會有簽收，也就不會觸發請款。
```

現在是 0 是正常的——批次還沒建。建完批次回來看就會變成
`這筆會看 4 個追蹤單元（僅 第一期），合計 76.0 噸`。

#### 四種觸發方式怎麼選

**看合約怎麼寫**：

| 合約長這樣 | 選這個 | 會產生幾筆錢 |
|---|---|---|
| 「簽約後 7 日內支付訂金」 | **手動** | 1 筆，會計自己按 |
| 「全數運抵並經簽收後請領」 | **該期全部簽收** | 1 筆，最後一批簽收時 |
| 「累計交貨達 80% 得請領」 | **累計重量達門檻**（填 80） | 1 筆，達門檻時 |
| 「按實際交貨數量分批請領」 | **每批按量分批請** | **N 筆**，每批一筆 |

**手動**是給系統判不出來的條件用的——「簽約後 7 日」系統看不到合約簽了沒，
「驗收合格」系統也不知道業主驗了沒。這兩種就讓會計自己按。

後兩種要靠**批次的總重量**算佔比，批次沒填重量就算不出來。

---

### 步驟 4｜建批次並歸到期別

**追蹤看板 → 新增**（或專案頁 → 新增追蹤單元）

| 欄位 | 填什麼 |
|---|---|
| 專案 | 台中廠房鋼構 |
| 階段流程 | 鋼構構件批次（9 站） |
| **期別** | **第一期** ← ★ 綁定的另一半 |
| 名稱 | 第一期-1F鋼柱 |
| 總數量 / 單位 | `24` / `支` |
| **總重量** | `31680`（公斤） ← 分批計價的分母 |

重複建第一期的其他批次。

> **總重量只有廠長／專案負責人／經營者能填**（決策 D19：職能分離）。
> 會計看得到錢但不能填重量，避免同一個人既決定計算基數又決定何時請款。

建完回到請款頁看檢查，那幾項應該都變綠了。

---

### 步驟 5｜現場作業（不用管請款）

批次沿著 9 站往前推。推到第 7 站「進場簽收 ✍💰」時，卡片上會出現橘色的「待簽收」。

貨到了、業主簽了名 → 點卡片 → **登錄簽收** → 填簽收人、日期、單號。

送出後系統立刻告訴你發生了什麼：

```
✔ 第一期-1F鋼柱 已登錄簽收
  已簽收 1/4 批，31.7/76.0 噸（41.7%）
  尚有 3 批未簽收
```

**還沒觸發**，因為合約寫「全數」。繼續簽其他三批，最後一批簽完：

```
✔ 第一期-桁架A區 已登錄簽收
  已簽收 4/4 批，76.0/76.0 噸（100.0%）
  已觸發請款：第一期請款 20,000,000 元
```

**這一刻，會計與經營者收到通知**（右上角 🔔 出現紅點）。
現場沒有人需要記得去講一聲。

---

### 步驟 6｜會計收款

**請款收款頁 → 請款事件分頁**，最上面多了一筆：

```
台中廠房鋼構 · 第一期請款
簽收自動產生 · 由「第一期-桁架A區」簽收觸發 · 9.6 噸
20,000,000                                    可請款
                                        [變更狀態]
```

點 **變更狀態**：

| 轉到 | 要填 |
|---|---|
| 已請款 | 請款日、請款單號（選填） |
| 已收款 | 收款日 |

**規則**：
- 不能跳過中間狀態（可請款 → 已收款會被擋）
- 往回轉（開錯單）**必須填原因**，會留在不可竄改的歷程裡

## 3. 手動型里程碑怎麼請

「簽約訂金」「完工尾款」這種手動型的，**不會自動產生請款事件**——
合約條件（「簽約後七日內」「驗收合格」）系統判不出來，由你自己按。

**請款收款頁 → 合約里程碑 → 找到那一筆 → 建立請款**

卡片上會直接有按鈕，底下寫著為什麼要手動。金額預設帶「剩餘可請金額」，
多數情況直接送出就好；要分次請也可以改小。超過剩餘金額會被擋。

建立後就跟自動產生的一樣，到「請款事件」分頁推狀態。

## 3.5 「該期全部簽收」到底怎麼觸發？

這是最常被問的。答案是：**觸發動作是「登錄簽收」，不是「推進階段」。**

### 三個步驟

```
① 把批次推到有 ✍ 的那一站     追蹤看板 → 點卡片 → 推進
      ↓
② 貨到了、業主簽了名 → 登錄簽收   追蹤看板 → 點卡片 → 登錄簽收
      ↓
③ 該期【每一批】都做完 ①②     → 系統自動轉「可請款」
```

**推到「進場簽收」那一站不算觸發。** 那只表示「我們送到了」。
簽收是業主的動作，我們控制不了——所以獨立成一個步驟（決策 D12／D13）。

卡片沒推到 ✍ 那一站時，**面板上不會出現「登錄簽收」按鈕**。
這不是壞掉，是還沒到那一步。

### 系統會直接告訴你還差哪幾批

不用自己數。**請款收款 → 合約里程碑**，那一筆卡片上會列出來：

```
第一期請款　該期全部簽收　只看 第一期
已簽收 0/4 批，0.0/76.0 噸（0.0%）

還差這 4 批簽收才會觸發
  第一期-桁架A區    加工       還要推 5 站到「進場簽收」才能簽收
  第一期-樓梯鋼構    置料區     還要推 3 站到「進場簽收」才能簽收
  第一期-1F鋼柱     出貨進場   還要推 1 站到「進場簽收」才能簽收
  第一期-樓板鋼樑    進場簽收   ← 可以登錄簽收了
```

**批次名稱是連結**，點了直接跳到看板並打開那張卡。
標「← 可以登錄簽收了」的就是現在能處理的。

### 每簽一批會看到進度

```
✔ 第一期-樓板鋼樑 已登錄簽收
  已簽收 1/4 批，26.3/76.0 噸（34.6%）
  尚有 3 批未簽收          ← 還沒觸發
```

簽到最後一批：

```
✔ 第一期-桁架A區 已登錄簽收
  已簽收 4/4 批，76.0/76.0 噸（100.0%）
  已觸發請款：第一期請款 20,000,000 元   ← 觸發了
```

### 四種觸發方式的動作對照

| 觸發方式 | 觸發動作 | 什麼時候發生 |
|---|---|---|
| 手動 | **按「建立請款」** | 你自己決定 |
| 該期全部簽收 | **登錄簽收** | 該期最後一批簽完的那一刻 |
| 累計重量達門檻 | **登錄簽收** | 累計噸數跨過門檻的那一刻 |
| 每批按量分批請 | **登錄簽收** | **每一批**簽完都會產生一筆 |

除了「手動」，其餘三種的觸發動作**都是登錄簽收**——差別只在系統的判斷條件。

### 常見誤會

| 以為 | 實際 |
|---|---|
| 推到「進場簽收」就會觸發 | 不會。要再按「登錄簽收」 |
| 簽收會讓卡片往下一站移動 | 不會。簽收不改變階段，兩件事分開 |
| 簽一批就可以請一部分 | 「該期全部簽收」不行，要全部。想分批請要選「每批按量分批請」 |
| 沒歸期別的批次也算 | 不算。里程碑綁第一期，就只看第一期的批次 |

## 4. 常見狀況

### 「我簽收了但請款頁什麼都沒有」

依序檢查（或直接看**請款設定檢查**）：

1. **這個案子有里程碑嗎？** 沒有 → 什麼都不會發生
2. **里程碑綁的期別，跟這批的期別一樣嗎？** 不一樣 → 對不上
3. **觸發條件達成了嗎？** 「該期全部簽收」要**全部**，簽一批不算
4. **重量填了嗎？** 按重量計價的兩種一定要填

簽收後系統回的訊息會直接說原因，例如 `尚有 3 批未簽收`、
`此批次未填寫總重量，無法計算分批金額`。

### 「金額算錯了」

金額＝**有效合約額 × 比例**。有效合約額＝原合約額＋已核准的變更追加單。

分批請款的每一筆＝**里程碑金額 × 該批噸數 ÷ 該期總噸數**。
分母（該期總噸數）在**首次觸發時就鎖定**，之後新增批次不會改變已算過的比例。

要改分母必須綁一張**已核准的變更追加單**——分母變了等於計價方式變了，
合約要一起改（決策 D20）。

### 「合約改了怎麼辦」

**專案頁 → 變更追加單**，建一張並送核准。核准後：
- 有效合約額改變
- **尚未產生請款的里程碑金額自動重算**
- 已經產生請款的**不動**——已經送出去的數字不能被改掉

### 「比例加總不是 100%」

設定檢查會提示。通常是漏了一條，或某一筆比例填錯。
建里程碑時「比例」欄位下方會即時顯示 `含這筆全案共 90%，還差 10%`。

## 5. 誰能做什麼

| 動作 | 經營者 | 專案負責人 | 會計 | 廠長 | 現場 |
|---|:--:|:--:|:--:|:--:|:--:|
| 看請款頁 | ✔ | ✔（自己的案） | ✔ | ✘ | ✘ |
| 建／改里程碑 | ✔ | ✔ | ✔ | ✘ | ✘ |
| 建期別 | ✔ | ✔ | ✘ | ✘ | ✘ |
| **填批次總重量** | ✔ | ✔ | **✘** | ✔ | ✘ |
| 登錄簽收 | ✔ | ✔ | ✘ | ✔ | ✘ |
| **轉請款狀態** | ✔ | ✘ | ✔ | **✘** | ✘ |
| 解鎖重量分母 | ✔ | ✘ | ✘ | ✘ | ✘ |

**廠長能填重量但不能轉請款；會計能轉請款但不能填重量**——
同一個人不能既決定請款金額的計算基數，又決定何時請款（決策 D19）。
