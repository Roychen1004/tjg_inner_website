## 1. 先釐清一個常見誤解

**Django Admin 不是給員工用的前端。**

| | Django Admin | React 前端 |
|---|---|---|
| 網址 | `http://<主機>:30080/admin/` | `http://<主機>:30080/` |
| 給誰用 | **只有系統管理員** | 全體員工 |
| 用來做什麼 | 設階段流程、建物品主檔、調系統參數 | 日常作業：看板、回報進度、簽收、請款、**維護客戶廠商員工** |
| 使用頻率 | 一個月幾次 | 每天 |
| 長什麼樣 | Django 預設的表格介面 | **像 POC 那樣**的看板與儀表板 |

**廠長、工地主任、師傅永遠不會看到 Django Admin。**

會這樣分是刻意的決定（決策 T03）。但實際使用後修正了一半（決策 D26）：
**客戶、廠商、員工搬到前端的「設定」分頁**——這三個是每週都會動的東西，
為了改一個客戶電話要跳到另一套介面，是把系統的複雜度轉嫁給使用者。

留在 Admin 的是**欄位多、動得少**的：物品主檔（依料型有不同尺寸欄位）、
位置階層、階段流程。Admin 的表單處理這種情況比自己刻一個好。

### 1.2 八個畫面各回答一個問題

| 畫面 | 回答的問題 | 誰看得到 |
|---|---|---|
| **我的工作** | 今天我該做什麼 | 現場人員、工地主任、廠長 |
| **總覽** | 公司現在整體狀況如何 | 除現場人員外全部 |
| **專案** | 這個案子進行到哪 | 除現場人員外全部（金額另外過濾） |
| **追蹤看板** | 東西現在卡在哪一站 | 除現場人員外全部 |
| **請款收款** | 錢收得回來嗎 | 經營者、專案負責人、會計 |
| **資產** | 公司有什麼東西、在哪、用在哪案 | 除現場人員外全部 |
| **產線** | 機台現在在忙什麼 | 經營者、專案負責人、廠長、品保、現場人員 |
| **設定** | 公司的客戶、廠商、員工資料 | 經營者、系統管理員 |

「一個畫面回答一個問題」是硬規則。答不出來的畫面就該砍掉，不是往裡面塞更多東西。

## 2. 系統運作原理

### 2.1 一句話

> **每個「東西」沿著一條可設定的流程往前走，走到特定站點時，系統自動做該做的事。**

### 2.2 三層結構

```
專案（承攬案）
  └─ 走一條主線：接案→深化設計→報價→採購備料→施工中→完工驗收→結案
     │
     └─ 底下有很多「追蹤單元」，各自平行推進
        │
        ├─ 鋼構案 → 構件批次，走 9 站
        │    進料驗收→加工→品檢→置料區→表面處理
        │    →出貨進場→【進場簽收】→安裝→收尾
        │
        └─ 土建案 → 工項，走 5 站
             放樣定位→施工中→自主檢查→監造查驗→【完成】
```

**關鍵特徵**：主線只有一條，底下的追蹤單元有很多條、且各自進度不同。

傳統的「專案完成 65%」這種單一數字，完全無法反映「1F鋼柱已進場、樓梯還在置料區、2F鋼柱送外廠噴砂」的真實狀況。

### 2.3 階段的五個旗標

流程不是寫死的，是資料。每一站可以帶五個旗標，告訴系統在這一站要做什麼：

| 旗標 | 系統行為 |
|---|---|
| 💰 **觸發請款** | 此站的完成條件達成 → 請款里程碑轉「可請款」，通知會計 |
| ✍ **需登錄簽收** | 需填簽收日／簽收人／單號。與💰併用時，改為**登錄簽收後**才觸發 |
| 🚚 **需填協力廠** | 沒填就列入「需要關注」 |
| ⏸ **等待中** | 不計入產能佔用（如置料區） |
| ⚙ **核心加值** | 工時計入 OEE 與加工成本 |

**鋼構第 7 站「進場簽收」同時帶 💰✍**，這是整個系統最重要的自動化。

### 2.4 為什麼簽收要獨立成一站

```
出貨進場  ←  我們的動作（裝車運出去）
進場簽收  ←  業主的動作（我們控制不了）
安裝      ←  我們的動作
```

如果把簽收併在「出貨進場」裡，「已送到但業主還沒簽」這個訊號就被藏起來了。

獨立成一欄後，看板上這些批次會**堆在第 7 欄**——**請款卡在哪，一眼看見**。系統還會在停留超過 7 天時自動提醒專案負責人去催。

### 2.5 請款的兩層結構

```
BillingMilestone（請款里程碑）  =  合約寫的條件
  「第一期請款 30%，該期構件全數運抵工地並經業主簽收」
        │
        └─ BillingClaim（請款事件）  =  實際可請的每一筆
```

分兩層是因為合約寫法不同：

| 觸發方式 | 何時產生請款 | 幾筆 |
|---|---|---|
| **手動** | 會計自己建 | 1 |
| **該期全部簽收** | 最後一批簽收時 | 1（全額） |
| **累計重量達門檻** | 累計噸數 ≥ 門檻（如 80%） | 1（全額） |
| **每批按量分批請** | **每批簽收各產生一筆** | N |

最後一種一個合約條件會產生多筆請款，單一狀態機表達不了「部分已請、部分可請、部分未到」——所以拆表。

**這就是「該期全部簽收」的意思**——合約寫「全數運抵並簽收」，所以簽一批不算數。系統告訴你還差幾批、目前幾成。

卡片會自己移到下一欄嗎？**不會**——簽收不改變階段。它只是記下「業主收了」。

### 步驟 3｜樓梯鋼構，順便看外包警告

「第一期-樓梯鋼構」在「置料區」欄（⏸ 等待中）。連按三次 **推進**：

「第一期-桁架A區」還在「加工」欄。一路 **推進** 到「進場簽收」，然後登錄簽收：

```
✔ 第一期-桁架A區 已登錄簽收
```

**這就是整個 P1 的核心價值：**現場的一個動作，直接變成財務上可以請的一筆錢，中間沒有人要記得去通知會計。

### 步驟 5｜確認副作用

**請款收款** 分頁 → 「請款事件」，最上面多了一筆：

```
固越企業總部案 · 第一期請款
簽收自動產生 · 第一期-桁架A區 · 9.6 噸
24,000,000                          可請款
                              [變更狀態]
```

點 **變更狀態** → 選「已請款」→ 填請款日與單號 → 送出。再變更一次到「已收款」。
試著直接從「可請款」跳到「已收款」，系統會擋下來：**不可跳過中間狀態**。
試著往回轉，系統要求**填原因**——錢的狀態被改過而沒人知道，是查帳時最麻煩的事。

右上角的 🔔 有紅點：會計與經營者都收到了「可請款」通知。

回到卡片 → **查看異動歷程**，每一次推進、誰做的、什麼時候，全部有紀錄，而且**改不掉也刪不掉**（連 superuser 都不行）。

### 步驟 6｜看第四種觸發方式的差別

看板篩選換成「南投國道橋樑鋼構」。它的里程碑設的是「**每批按量分批請**」：

```
分批交付計價　90% = 5,040 萬

桁架 B 區　28 噸　佔 40.0%
```

把「桁架 A 區」推到「進場簽收」並簽收：

```
✔ 已登錄簽收
  已觸發請款：分批交付計價 30,240,000 元
  本批 42.0 噸，佔該期 60.0%，可請 30,240,000 元
```

**只簽一批就能請款 3,024 萬**，不用等另一批。這跟固越案「全部簽收才算」完全不同——**合約怎麼寫，系統就怎麼設**。

到 **請款收款 → 合約里程碑**，這一筆會顯示 🔒 **分母已鎖定 70.0 噸**。之後再新增批次，也不會改變已經算出來的 60%——要改，必須綁一張已核准的變更追加單（決策 D20）。

## 4. 各角色實際怎麼用

| 角色 | 主要畫面 | 每天做什麼 | 裝置 |
|---|---|---|---|
| **經營者** | 營運總覽 | 看哪裡卡住、錢收得回來嗎 | 桌機 |
| **專案負責人** | 專案 ＋ 需要關注 | 追自己的案子、對客戶交代 | 桌機／手機 |
| **廠長** | 追蹤看板 ＋ 產線 | 排產、看批次卡在哪一站 | 桌機 |
| **工地主任** | 我的工作 ＋ 看板 | 回報工項進度、登錄簽收 | **手機** |
| **現場師傅** | 我的工作 | 回報今天做了幾支 | **手機** |
| **會計** | 請款收款 | 開請款單、追收款 | 桌機 |
| **採購／倉管** | 資產 | 查料、追料、找餘料、入庫、領用 | 桌機 |
| **系統管理員** | **設定**分頁 ＋ Django Admin | 前端管客戶廠商員工；Admin 管物品、位置、階段流程 | 桌機 |

現場師傅的「我的工作」實際長這樣：

```
┌─────────────────────────┐
│ 我的工作          🔔 陳 │
├─────────────────────────┤
│ 固越企業總部案 · 第二期  │
│ 第二期-2F鋼柱     ● 注意 │
│ 目前在 加工 (第2/9站，3天)│
│ 20 / 64 支              │
│ ▓▓▓░░░░░░░░░░░░  31%    │
│ ┌────────┬──────────┐   │
│ │ ＋1 支 │ 下一步 → │   │  ← 只有兩個按鈕
│ └────────┴──────────┘   │     觸控區 ≥ 44px
└─────────────────────────┘
```

點卡片本身會打開完整面板，裡面的快速按鈕級距**由後端依單位決定**——噸給 `+0.5 / +1 / +5`，支給 `+1 / +5 / +10`。前端沒有寫「如果單位是噸就…」這種判斷。
