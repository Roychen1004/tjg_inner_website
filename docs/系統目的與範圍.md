# 系統目的與範圍

## 目的

鐵正綱工程的內部管理系統。取代 Excel、紙本與 LINE 追蹤，回答四個問題：

1. **案子做到哪**——每個案子照「五大階段 × 19 工作項」的流程目錄追蹤，
   每一步排給誰、排到什麼時候、卡住了沒（專案卡片直接看迷你甘特）
2. **今天輪到我做什麼**——員工登入「我的任務」接任務、回報、按完成
3. **錢在哪**——該收的收了沒（應收，觸發流程完成自動轉可請款）、該付的付了沒（應付，逐筆掛流程）
4. **未來會不會缺錢**——收付加總的現金流預測，累計轉負的那一格

## 範圍（2026-08-14 流程制改版後）

**做**：從詢價就建案（生命週期：進行中/未成交/暫停/已結案；估價金額進預測）、
建案勾流程生成流程單元（目錄順序固定，只能勾選不能重排）、指派與站內通知、
流程單元的工作項目清單（內容物＋數量＋自訂狀態，如「鐵材 500 噸：已下訂單」）、
我的任務、構件批次七站（在專案明細管理，過站自動彙總回階段 4 流程）、
專案主線由流程進度**自動判定**（不手動推進，可同時兩階段進行）、
日曆甘特（滾輪縮放、拖曳平移＋專案多選）與甘特圖 Excel 下載、
專案刪除（限經理；有請款收款紀錄的擋下）、
應收四狀態（期別掛觸發流程）、
應付三狀態（核可與付款分離、逐筆掛流程單元）、現金流預測（三級確定性）、
專案損益、附件（合約/圖說/照片/流程產出物，含權限與防護）。

**不做**（要用時從 git 或封存文件恢復）：
庫存/資產/產線管理、KPI 快照排程、薪資與簽核流程。正式帳務仍由會計軟體處理。

## 使用者

四種角色（D40）：**經理**＝系統管理員（看全部、改全部）、
**會計師**（看全部頁面，只改金流與自己的任務）、
**員工**（繪圖師/行政人員/工廠員工——除金流外都看得到但唯讀、無金額，
只能動「我的任務」）、**檢視**（保留備用）。
帳號與密碼：`帳號密碼.md`。

## 硬約束

- 正式機 8GB RAM：常駐目標 ≤1.5GB
- 響應式網頁，非 App；正式環境無 Node 程序
- 六個分頁，每個畫面回答一個問題；元素通不過「砍掉會有人做不了事嗎」就砍
- 流程目錄的**順序**對使用者永遠唯讀——「訂料一定排在放樣收點後面」是制度，不是選項
