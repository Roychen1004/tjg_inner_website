### 📗 系統目的與範圍.md
給老闆：**為什麼要花錢做這個**。六大隱性成本（合計逾 1,200 萬／年）、
成功衡量指標、做什麼／不做什麼的邊界、與現有會計軟體的分工。

### 📙 決策紀錄.md
給老闆：**29 個決策逐條確認**。每則都是「一問一答」＋推翻成本，
可以直接勾選或標註要改的項目。標 ⚠️ 的是改動成本高的，請優先確認。

### 🛠 部署手冊.md
**在新電腦上把系統架起來。** 裝 Docker → 建 `.env` → 建置啟動 → 載主檔 →
驗收 → 上線前必做。每一步都在乾淨環境跑過一次，含五個實際踩過的坑
（套件名稱、CSRF 埠號、logs 權限、restart 不重讀 env、正式機要排除 override）。

帳號、密碼、pgAdmin 設定。**要登入就會用到，所以放在最上層。**

## 權威來源不是文件，是程式碼

```
資料表實際長什麼樣    → main/apps/*/models/ 的 docstring
API 實際有什麼        → /api/v0.1/swagger（從程式碼產生）
業務規則實際怎麼跑    → main/apps/*/services/
誰能做什麼            → main/utils/permissions.py、scoping.py
```

**文件會過期，程式碼不會。** 所以凡是能從程式碼產生的，就不手寫一份——
手寫的 API 規格已經開始跟實際不符，那就是它被封存的原因。

## 文件為什麼這樣分

**第一性原理：一份文件只服務一種讀者。**

同一份文件同時想給員工看操作、給老闆看決策、給工程師看資料表，
結果是三種人都要跳過三分之二的內容——認知負荷來自「找不到我要的那一段」，
不是來自「字太多」。

原本 16 份、10,406 行，員工要翻 4 份才知道怎麼用。
現在**員工只翻 1 份**，老闆 2 份，工程師的東西收在子目錄裡不干擾。
