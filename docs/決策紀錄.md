## D57｜2026-09-08　薪資：依法規算，法規參數全部可編輯　★本輪

老闆要的是「會計師不用再拿計算機對打卡表」。原本給的是一份 Excel 範例
（`docs/template/薪資明細範例.xlsx`），但那份表的算法有幾處低於法定標準，
所以最後**不照它的公式做，改成照現行法規算**。

1. **不照 template 的公式**——那份表把加班倍率寫成 1.33／1.66，
   而勞動部建議用 **1.34／1.67**：法條寫「加給三分之一**以上**」，
   四捨五入後 1.33 會低於法定下限，少給就是違法。
   （template 另有一處合計是 `=小計-扣款-1`，那個 −1 沒有依據，是手動微調。）
   保留下來的只有兩件事：**員工福利金 1%**（公司自訂，按應發總額計）
   與**把算式攤在畫面上**——後者其實是那份 Excel 最好的地方，
   會計師是照著算式驗算的，只給總額她不會信，最後還是自己再算一次
2. **法規參數一個都不寫死**（`payroll_policy` 一張表，全部是可編輯欄位）。
   基本工資每年調、勞健保費率隔幾年動一次，烤進程式等於每次修法都要
   改程式、重建映像、重新部署——而那件事會拖到她算不出這個月的薪水。
   預設值填 115 年（2026）現行法規：最低時薪 **196**、
   勞保 12.5%（勞工負擔 20%）、健保 5.17%（本人 30%、眷屬上限 3 口）、
   勞退雇主提繳 6%。驗算：投保 29,500 → 勞保自付 **738**、健保 **458**／口，
   與勞保局對照表一致（也與 template 裡出現的數字一致）
3. **確認時凍結參數快照**（`PayrollPeriod.policy_snapshot`）——
   明年調基本工資，不能回頭改動去年 12 月的薪資單（鐵律 5）。
   已確認的月份鎖定，要改必須先退回草稿；**已發放的不能退**——
   錢匯出去了，改帳面追不回來，有差額在下個月用加項扣項補正
4. **工時自動帶出來**：應上班天數＝當月平日 − 國定假日（內建 2026 行事曆，
   可增刪），薪資單預設工時＝`天數 × 每日正常工時`，加班預設＝`天數 × 每日固定加班`。
   8:00–17:30 扣 1 小時休息＝8.5 小時，其中 8 小時是正常工時、多的 0.5 算加班——
   所以固定加班預設 0.5 小時／天。這三個數字在畫面上都能改
5. **薪資另立權限碼，不共用 `view_money`**（`view_payroll` / `edit_payroll`
   ＝經理＋會計師＋系統管理員）。金流看的是公司對外的錢，薪資看的是
   **同事領多少**——那是連「看得到金額」的人都不該順便看到的東西。
   員工與檢視角色連分頁都不存在，直接打 API 也是 403（驗收有擋這條）
6. **員工名冊直接取 `core.User`**，不另建一份——兩份名冊遲早對不起來
   （誰離職了、誰改名了）。「同步員工名冊」按一下替新人補上薪資設定

### 第二輪（2026-09-09）：誰要算、不滿一個月怎麼算

7. **誰不算薪水**：停用的帳號（離職的人不該每個月又長出一張薪資單）與
   **superuser（系統管理員 admin）**——那是系統維護用的身分，不是員工。
   已建立的 admin 薪資設定用 migration 停用而不刪除（`0004_drop_superuser_profiles`）
8. **到職／離職不滿一個月**（`SalaryProfile.hire_date` / `resign_date`）。
   ⚠️ 三種保險的未滿月規則**各不相同**，這是整個功能最容易算錯的地方：

   | | 規則 | 到職當月 | 離職當月 |
   |---|---|---|---|
   | 勞保、勞退 | 按日，**分母一律 30**（不分大小月） | 30 − 到職日 + 1 | 離職日 |
   | 健保 | **不按日**，整月計收 | 照收（月底人在公司） | 月中走＝**不收**，月底走＝收整月 |
   | 工資 | 按實際在職期間的**平日數** | | |

   最容易錯的是 2 月：2/2 到職做到 2/28（月底）是 **29 天**不是 27 天——
   分母是 30，做到月底就算到第 30 天，少算的那兩天是勞工的錢。
   `workday_service` 有 11 個案例的驗算。三個算出來的值（應上班天數、
   勞保勞退天數、健保收不收）都在畫面上可以改
9. **時數一律取到 0.5 小時**。打卡表本來就是以半小時在看的（8:00–17:30
   那半小時就是這樣來的）。允許 0.1 小時只會讓人在「6 分鐘」上爭執，
   而那 6 分鐘不會有人真的去記。輸入 7.3 會收成 7.5 並**立刻顯示出來**——
   靜靜改掉使用者打的數字是不行的
10. **雇主負擔也算出來**（薪資單的「雇主另負擔」區塊）：勞保 70%、
    健保 60% × **1.56**、勞退 6%。「請一個人要花多少」不只是他領到的數字。
    ⚠️ 健保雇主負擔**不看員工實際有幾個眷屬**——一律用全國平均眷口數
    （2024 起 0.57 → **0.56**，故計費人數 1 + 0.56 = 1.56）。
    所以員工多加保眷屬，多出來的錢全是員工自己付，公司負擔不變。
    驗算：29,500 × 5.17% × 60% × 1.56 = **1,428**——這個數字也正好出現在
    老闆給的 template 裡（員工1 的扣款明細），反推對得起來

### 第三輪（2026-09-09）：修 bug、月曆確認、法規說明與級距原檔

11. **修掉「填了到職日卻沒生效」**（老闆回報）。原因是 `generate` 對**已存在**的
    薪資單只跳過不更新，而「先產生薪資單、後補到職日」才是實際發生的順序。
    改成：每次產生都重新帶入「日期算得出來的」五個欄位（應上班天數、正常工時、
    固定加班、勞保勞退天數、健保計收），手填的加班／請假／遲到早退／加扣項不動；
    連手填的也要歸零才帶 `?reset=true`。順便補兩件事：**該月不在職的人若還留著
    薪資單就收掉**（數字是錯的），以及比較用值不用字串
    （`Decimal("20.00")` 與 `Decimal("20")` 是同一個數，字串比會讓它每次都說「全部更新了」）
12. **新增月份時把整個月攤成月曆**（`suggest` 多回一個 `days` 陣列）。
    四種顏色：上班日、一般假日（週末）、國定假日、補班日；
    **非一般的日子直接寫出名字**（國慶日、元旦、補假）。
    只給「20 天」這個數字她沒辦法判斷對不對，攤開才看得出來扣的是哪兩天。
    `Holiday.is_workday` 是為補班日留的——2026 年已取消補班，但制度改回來時
    不必再動程式
13. **「法規參數」改名「設定與法規」**，下分三個子頁：
    - **參數設定**——原本的可編輯欄位
    - **法規說明**——三種保險各保什麼、誰出多少、未滿月怎麼算、員工能選什麼。
      ★ 例子裡的每個數字都是**由當前參數即時算出來的**，不是寫死的字串：
      改了費率例子跟著變，否則參數改了說明沒改，這頁就開始騙人
    - **級距**——政府公告的三份原檔（見下）＋系統採用的級距表
14. **把政府公告的級距原檔放進系統**（`main/apps/payroll/static/payroll/`，
    走 nginx 的 `/static/` 出去，清單與中繼資料在 `payroll/reference.py`）：
    勞保投保薪資分級表、勞工退休金月提繳分級表、全民健康保險投保金額分級表，
    都是 115.1.1 生效版。會計師不必再去三個網站找。
    ⚠️ 健保署網站擋自動存取（HTML 頁面一律 403），檔案是繞道網頁典藏庫
    找到直連網址才抓到的——明年更新時如果一樣抓不到，就人工下載放進去，
    步驟寫在 `reference.py` 的檔頭

### 第四輪（2026-09-09）：自動套用、行事曆匯入、投保級距把關

15. **員工設定改完就生效，不必再按「產生薪資單」**（老闆回報第二次）。
    上一輪雖然讓 `generate` 會更新已存在的薪資單，但使用者的操作順序是
    「填到職日 → 回月薪資看」，中間沒有人會記得要多按一個鈕。
    改成 `SalaryProfile` 存檔時自己套進**所有草稿月份**
    （`apply_profile_to_drafts`）：在職就更新或補建、不在職就把那張收掉。
    已確認／已發放的月份不動——那是凍結的歷史
16. **國定假日改成從政府資料開放平臺匯入**（`calendar_import`）。
    原本只內建 2026，要算 2027 就沒資料。資料源是 dataset 14718
    「中華民國政府行政機關辦公日曆表」（人事行政總處公告的 CSV，一年一檔，
    欄位 `西元日期,星期,是否放假,備註`）。每年的檔案網址是一串 uuid、
    每年都不同，所以要先打資料集 API 找當年度那一筆，不能寫死。
    只匯入**跟預設規則不一樣**的日子（平日放假、週末上班），
    一般的平日上班與週末放假不記——記了只是讓表變大。
    ⚠️ 要連外網。正式機在區網可能連不出去，所以是**手動按的**不是排程，
    失敗時講清楚原因，會計師仍可一天一天手動加
17. **投保級距對不上當月薪資會示警**（老闆要求）。勞保條例規定投保薪資要按
    實際月薪資總額申報，高報低報都違法。系統拿應發總額對照分級表，
    不一致就在薪資單上標出來。
    ⚠️ **只在整月在職時檢查**——到職／離職不滿一個月的人這個月本來就領得少，
    拿它去比會一律誤判成「高報」。
    ★ 實測發現：最低時薪 196 × (160 正常 + 10 加班) 的應發是 **33,986**，
    對照分級表應申報 **34,800** 而不是預設的 29,500——公司現在的申報是低報的
18. **已發放也能退回草稿**（老闆指示，推翻上一輪的設計）。原本擋掉是因為
    「錢匯出去了改帳面追不回來」，但那是老闆的決定。改成放行，
    並在期間備註留下「誰、什麼時候退的」——之後有人問「帳跟匯款單怎麼對不起來」
    至少查得到。畫面上仍然寫著建議做法是下個月用加項扣項補正
19. **三個頁面的字級全部放大一階**（老闆要求，同 D50 的全站字級放大）
20. **「設定與法規」多一個「行事曆」子頁**：匯入、逐年檢視、手動增刪
    （颱風停班這種政府檔案裡沒有的，自己加）。
    新增薪資月份時若該年度還沒有假日資料，對話框裡就地提供匯入鈕
21. 順手修掉重複建立月份時噴 DRF 英文原文
    （`The fields year, month must make a unique set.`）——
    model 的 `UniqueConstraint` 會自動產生驗證器搶在 `validate()` 前面丟出，
    要在 serializer 的 Meta 設 `validators = []` 才輪得到自己的中文訊息（鐵律 9）

### 第五輪（2026-09-09）：級距只留連結、薪資 Excel

22. **級距頁不放 PDF 副本，只留官方頁面連結**（老闆指示，推翻第三輪）。
    上一輪把三份公告的 PDF 收進 `static/payroll/`，但法規每年修——
    留副本就會有「系統裡那份是舊的」的問題，而那比多點一次連結危險得多。
    檔案刪掉、`reference.py` 只留 `source`
23. **產生薪資單時可以下載 Excel**（`payroll_export`，
    `GET /payroll-periods/{id}/xlsx`）。三張表，照會計師接下來真的要做的事排：
    - **薪資總表**——每人一列，出勤與金額全在同一張，合計列用 `=SUM()` 公式
      （不是寫死的數字，改了還會自己算）
    - **計算明細**——每一行的「項目 × 算式 × 金額」。
      ★ 這張才是重點：系統存在的理由就是把算式攤開，匯出去也不能只剩數字，
      否則印出來的東西跟她原本的 Excel 一樣不能驗算。算式欄用等寬字
    - **銀行匯款**——編號、姓名、實發金額。她核完的下一步就是拿這個去匯款

    刻意**不**做 template 那種「一頁四張、附簽名處」的列印版面——
    那是為了簽名而存在的格式，要不要保留還沒確認；要的話再加第四張表

### 第六輪（2026-09-09）：安全的自動、會覆蓋的才要按鈕

24. **拿掉「產生薪資單」，改成「重設工時」**（老闆問「都改成全自動是不是就
    不用那顆按鈕」，討論後選了折衷）。那顆鈕本來同時做兩件性質不同的事：

    | | 能不能自動 | 現在怎麼做 |
    |---|---|---|
    | 建立缺少的薪資單 | ✅ 安全 | 自動 |
    | 更新勞保勞退天數、健保收不收 | ✅ 安全 | 自動 |
    | 移除當月不在職者 | ✅ 安全 | 自動 |
    | **帶入工時基準值** | ⚠️ **會覆蓋手 key 的資料** | 「重設工時」鈕 |

    自動的部分（`sync_records`）掛在建立月份、改期間設定、改員工設定、
    同步名冊、重算薪資、確認前。所以**會計師不必記得按任何按鈕**——
    前面兩輪的 bug 都是「忘記按」造成的，這樣整類問題就消失了。

    ⚠️ 踩到的坑：一開始用「算出來的天數跟記錄裡的不一樣」判斷「在職期間變了」
    就重帶工時——結果改期間的應上班天數也會讓天數不一樣，照樣把 key 到一半的
    資料洗掉。改成傳 `rebaseline_users`：只有**那個人的設定被改**時才准重帶他的工時
25. **「重設工時」按下去先問清楚**：對話框列出「會被蓋掉的」與「不會動到的」，
    另有一個勾選「連手填的加班請假遲到早退一起歸零」（＝原本的 `?reset=true`，
    現在叫 `?deep=true`）。會覆蓋資料的動作不該一鍵就發生
26. **修掉「停用之後開不回來」**：`SalaryProfileViewSet.get_queryset` 對所有 action
    都濾掉 `is_active=False`，連 PATCH 都找不到那筆——「不納入薪資計算」變成
    單向門，使用者只會看到 404。改成只有 list 才過濾，而且預設把停用的也列出來
    （畫面上灰掉），並補上「納入薪資計算」的勾選框
27. **修掉 `verify.py` 的時區 bug**（跑驗收時發現的，跟薪資無關）：
    腳本用**宿主機**的 `date.today()` 建測試資料，但系統時區是 Asia/Taipei。
    台北的凌晨 0–8 點（UTC 16–24 點）宿主機還停在前一天，
    用那個日期建的行政事項會被「只看未來」的現金流預測濾掉——
    驗收在每天那 8 小時會無故失敗。改成用 `ZoneInfo(TIME_ZONE)` 算今天

## D56｜2026-09-04　行政事項：類別在表單裡開、金額多一個「參考」
