## 1. 這份文件要解決的問題

手冊第 3 章：**「不能衡量，就不能管理。」**

手冊已經定義了 18 項 KPI 與 8 組成本公式，但每一條都需要**資料**才算得出來。
這份文件把每一條公式對應到：**資料從哪張表來、什麼時候算、算不出來的時候怎麼辦。**

### 1.1 一個誠實的提醒

> ⚠️ **第一階段（P1）做完，18 項 KPI 一項都算不出來。**

因為 P1 只收集專案與進度資料，KPI 需要的是採購、庫存、工時、檢驗、出貨資料。
硬要在 P1 顯示 KPI，只會顯示一堆 0 或假數字——那比沒有更糟。

**P1 該做的是**：把 KPI 需要的**資料結構先鋪好**（例如回退原因分類、階段停滯時間），
並提供 4 項**用 P1 資料就算得出來的先行指標**（見 §3）。

| 階段 | 可計算的 KPI 數 | 說明 |
|---|---:|---|
| P1 | 0 / 18（＋4 項先行指標） | 只有進度資料 |
| P2 | 6 / 18 | 加上採購與庫存 |
| P3 | 16 / 18 | 加上生產、品質、交付 |
| P4 | 16 / 18（＋薪資自動化） | Cpk 與程式重用率需額外系統 |

## 2. 系統參數表（可設定常數）

手冊 13.5 明確指出三大核算陷阱之一是**「費用率不更新，多年沿用舊值導致失真」**。
因此所有常數**不寫死在程式裡**，存在 `core_systemparameter` 表，**帶生效日期**。

### 2.1 `core_systemparameter`

| 欄位 | 型別 | 說明 |
|---|---|---|
| `code` | varchar(50) | 參數代號 |
| `name` | varchar(100) | 中文名稱 |
| `value` | numeric(18,6) | 數值 |
| `unit` | varchar(20) | 單位 |
| `effective_from` | date | **生效日** |
| `effective_to` | date NULL | 失效日（NULL = 仍有效） |
| `source_note` | text | 依據說明（例如「依 2026 年度預算」） |
| `updated_by` / `updated_at` | | |

**約束**：`UNIQUE(code, effective_from)`；查詢時取 `effective_from <= 目標日 < effective_to` 的那筆。

> 💡 **帶生效日期的意義**：2026 年的訂單要用 2026 年的製造費用率核算，
> 不能因為 2027 年更新了費用率，就讓 2026 年的歷史成本跟著變。

## 3. P1 先行指標（用 P1 資料就算得出來）

這 4 項不在手冊的 18 項裡，但**P1 就能算，且是後續 KPI 的先行訊號**。

| 指標 | 公式 | 目標 | 警示 | 資料來源 | 意義 |
|---|---|---|---|---|---|
| **資金收攏率** | 已收款金額 ÷ 有效合約額 | ≥ 60% | < 40% | `billing_billingmilestone` | 現金流健康度 |
| **平均階段停滯天數** | Σ(各單元在目前階段的天數) ÷ 單元數 | ≤ 5 天 | > 10 天 | `tracking_trackingunit.stage_entered_at` | 流動順暢度；**OEE 的先行指標** |
| **回退率** | 回退次數 ÷ 總階段異動次數 | ≤ 3% | > 8% | `tracking_trackingunitstagelog.direction` | **品質失敗成本的先行指標**（手冊 11.3） |
| **外包在外天數** | Σ(進廠至今天數) ÷ 在外批數 | ≤ 14 天 | > 21 天 | `tracking_trackingunit` 外包欄位 | 料在外面失聯的風險 |

> 💡 **「回退率」是最有價值的 P1 指標**：每一次回退都填了原因分類（`reason_category`），
> 這些資料累積一年後，到 P3 就能直接算出 PAF 模型的「內部失敗成本」——
> 不用等 P3 才開始收集。

### 4.2 需要特別定義的計算細節

#### KPI-1 OEE 設備總效率（手冊第 10、17 章）

```
OEE = 可用率 × 效能 × 良率

可用率 = 實際運轉時間 ÷ 計畫生產時間
效能   = (實際產量 × 理論週期時間) ÷ 實際運轉時間
良率   = 良品數 ÷ 總產量
```

| 項目 | 規格 |
|---|---|
| **計算範圍** | 單一設備／單一班別／單日 |
| **計畫生產時間** | 班別時數 − 計畫停機（保養、教育訓練、無訂單） |
| **實際運轉時間** | 計畫生產時間 − 非計畫停機（故障、換線、缺料、待工） |
| **理論週期時間** | 由 `RoutingStep.standard_cycle_time` 提供 |
| **資料來源（P3）** | 現場報工 `WorkReport` ＋ 停機紀錄 `OeeLoss` |
| **計算時機** | 每日 02:00 由 `calc_daily_kpi` 產生前一日快照 |
| **邊界情況** | 計畫生產時間 = 0（無排產） → **不計入平均**，不是算成 0% |
| **公司彙總** | 各設備 OEE 依「計畫生產時間」**加權平均**，不是算術平均 |

**成本意義**（手冊 10.5）：
```
理論滿載產能價值 = 80,000,000
OEE 60% → 實際產出 48,000,000
OEE 75% → 潛在產出 60,000,000
增加產值 12,000,000 × 邊際貢獻 30% ≈ 增加獲利 3,600,000/年
```

**六大損失分類**（`OeeLoss.loss_type`，手冊 10.6）

| 代碼 | 損失 | 影響 | 對策 |
|---|---|---|---|
| `breakdown` | 設備故障 | 可用率 | TPM 預防保養 |
| `changeover` | 換線調整 | 可用率 | SMED（第 18 章） |
| `minor_stop` | 小停頓空轉 | 效能 | 自動偵測、消除卡料 |
| `speed_loss` | 速度降低 | 效能 | 回復標準轉速、刀具管理 |
| `defect` | 製程不良 | 良率 | SPC、防錯設計 |
| `startup_loss` | 啟動損失 | 良率 | 首件確認、暖機標準化 |

#### KPI-5 平均換線時間（手冊第 9、18 章）

```
平均換線時間 = Σ 換線時間 ÷ 換線次數

單次換線成本 = 換線時間(h) × (人工真實時薪 + 設備閒置成本)
             = 1.25 × (450 + 250) = NT$ 875/次      ← 手冊 9.3 範例
年度換線成本 = 875 × 150 次/月 × 12 = NT$ 1,575,000
```

| 項目 | 規格 |
|---|---|
| **計時起點** | 前一工單最後一個良品產出 |
| **計時終點** | 下一工單第一個良品產出 |
| **資料來源** | `ChangeoverLog`（現場以「開始換線／換線完成」兩鍵記錄） |
| **內部／外部作業** | 依 SMED 分類（手冊 18.2），分別統計 |

> 💡 **這個 KPI 的價值在複利效應**（手冊 9.3）：
> 每次換線多花 20 分鐘 × 150 次/月 = 每月多燒 50 小時，年度多損失 42 萬。

#### KPI-7~9 品質成本 PAF 模型（手冊第 11、19 章）

```
品質總成本 = 預防 + 鑑定 + 內部失敗 + 外部失敗

  鑑定成本   = 檢驗工時 × 檢驗人員真實時薪 + 外部檢測費
  內部失敗   = 重工工時 × 真實時薪 + 報廢品完全成本
  外部失敗   = 客戶賠償 + 處理工時成本 + 商譽損失估列
  預防成本   = 教育訓練 + 防錯設計投入 + SPC 導入 + 供應商輔導
```

**鐵正綱現況診斷**（手冊 11.4）

| PAF 類別 | 金額 | 占比 | 理想 | 診斷 |
|---|---:|---:|---|---|
| 預防 | 800,000 | 8% | 15–20% | ⚠️ **偏低** |
| 鑑定 | 4,220,090 | 42% | 20–30% | ⚠️ **偏高** |
| 內部失敗 | 2,840,000 | 28% | 越低越好 | 待改善 |
| 外部失敗 | 2,120,000 | 21% | 越低越好 | ⚠️ 偏高 |

> **診斷結論**（手冊 11.4）：典型的「重檢驗（42%）、輕預防（8%）」模式，
> 導致失敗成本高達 50%。正解是把資源從「鑑定」前移到「預防」。

**1-10-100 法則**（手冊 11.3）——同一缺陷在不同階段發現，成本差 100 倍：

| 發現階段 | 相對成本 | 系統中的判定 |
|---|---:|---|
| 預防階段（改設計、改流程） | 1 | `DefectRecord.found_at_stage` = 設計／進料 |
| 廠內檢驗發現（重工、報廢） | 10 | `found_at_stage` = 品檢／製程 |
| 客戶端發現（客訴、退貨、賠償、商譽） | 100 | `CustomerComplaint` |

**P1 就開始收集的資料**：`TrackingUnitStageLog.reason_category`
（`qc_fail`／`dimension_error`／`material_issue`／`workmanship` 全部歸入內部失敗）

#### KPI-12 準時交貨率 OTD（手冊第 12 章）

```
OTD = 準時交貨批數 ÷ 總交貨批數
```

| 項目 | 規格 |
|---|---|
| **「準時」的定義** | 實際交貨日 ≤ 客戶要求交期 |
| **寬限期** | ⚠️ **待確認**：是否給 1 天寬限？ |
| **計算單位** | 以「出貨批」為單位，不是以「專案」 |
| **資料來源** | `Shipment.planned_date` vs `DeliveryReceipt.received_date` |

**手冊 12.8 的系統觀**：OTD 低不能只怪交付部門，根因常在生產換線或品質重工。
因此系統要能**下鑽到延誤原因**：

```
OTD 未達標
├─ 採購端：料未準時到（PO 逾期）
├─ 生產端：產能不足（OEE 低／換線多）
├─ 品質端：不良重工延誤（回退次數）
└─ 交付端：排程與運力不足
```

**業界數據**（手冊 12.3）：OTD 每下降 1%，客戶流失率上升 2–3%。

#### KPI-15 庫存週轉率（手冊第 8 章）

```
庫存週轉率 = 年銷貨成本 ÷ 平均庫存值
平均庫存值 = (期初庫存 + 期末庫存) ÷ 2      ← 或用月底餘額的 12 個月平均（較準）
```

| 項目 | 規格 |
|---|---|
| **計算週期** | 滾動 12 個月 |
| **平均庫存** | 取**月底餘額的 12 個月平均**，比期初期末平均準確 |
| **資料來源** | `StockLot.value`（每月底快照存 `CostSnapshot`） |

**改善效益試算**（手冊 8.7）：
```
現況：100,000,000 ÷ 25,000,000 = 4 次/年
目標：週轉率 6 次 → 所需平均庫存 = 100,000,000 ÷ 6 ≈ 16,670,000
釋放資金 = 25,000,000 − 16,670,000 = 8,330,000
節省資金成本 = 8,330,000 × 3.5% ≈ NT$ 291,550/年
```

#### KPI-16 呆滯料佔比（手冊 8.4）

**呆滯分級**（依最後異動日至今天數）

| 狀態 | 天數 | 處置時程 | 處置方向 | 系統行為 |
|---|---|---|---|---|
| 正常 | < 30 | 無需處理 | 維持，監控週轉 | — |
| 緩動 | 30–90 | 觀察期 | 追蹤需求預測 | 列入報表 |
| 滯銷 | 90–180 | 立即評估 | 轉用／降價／退回 | **計入呆滯料佔比** ＋ 通知倉管 |
| 呆滯 | 180–365 | 強制處置 | 執行處置方案 | 通知倉管 ＋ 經營者 |
| 報廢候選 | > 365 | 認列損失 | 報廢，釋放空間 | 強制列入季度棄舊檢視 |

```
呆滯料佔比 = (庫齡 > 90 天的庫存值) ÷ 總庫存值
```

由 `scan_alerts` 每日掃描並更新 `StockLot.aging_status`。

#### KPI-18 採購人力成本占比（手冊 7.3、7.4）

```
單筆採購人力成本 = 採購工時(10h) × 採購人員真實時薪(378)
                 = NT$ 3,780

採購人力成本占比 = (採購單數 × 3,780) ÷ 採購總額
```

**經濟採購量原則**（手冊 7.4）

| 採購金額 | 人力成本 | 占比 | 評估 |
|---:|---:|---:|---|
| 5,000 | 3,780 | 76% | 🔴 嚴重不合算 |
| 30,000 | 3,780 | 13% | 🟡 勉強 |
| **75,000** | 3,780 | **5%** | 🟢 **經濟門檻** |
| 500,000 | 3,780 | 0.8% | 🟢 優秀 |

**系統行為**：請購單金額 < `min_purchase_amount`（75,000）時，
**主動提示**「本筆採購人力成本占比 X%，建議與其他需求合併下單」——
這是把手冊 7.4 的效能思維寫進系統。

### 4.3 兩項需要額外投入的 KPI

| KPI | 為何算不出來 | 建議 |
|---|---|---|
| **KPI-6 程式重用率** | 需要 NC 程式庫管理系統，記錄每次加工是「調用既有程式」還是「新編程式」 | P3 加一張 `NcProgram` 表，工單開立時選擇程式來源即可 |
| **KPI-11 製程能力 Cpk** | 需要 SPC 量測資料（每件的實際尺寸），不是只記合格／不合格 | 需要量測設備連線或人工登錄量測值。**建議先做手冊 19.5 提到的 SPC 導入評估，再決定是否納入系統** |

## 5. 成本計算公式（附錄 B）

### 5.1 真實時薪（最基礎、最常用）

```
真實時薪 = 月薪 × 年薪倍數(13.5) ÷ 年有效工時(1600) × (1 + 附加率)
```

**範例**

| 職類 | 月薪 | 附加率 | 真實時薪 | 表面時薪 | 倍率 |
|---|---:|---:|---:|---:|---:|
| 採購助理 | 35,000 | 0.28 | **378** | 199 | 1.9× |
| 焊接技師 | 40,000 | 0.20 | **432** | 227 | 1.9× |
| 焊接技師（另一附加率） | 40,000 | 0.22 | **412** | 240 | 1.7× |

> ⚠️ **手冊中同一職類有兩個數字（432 與 412）**，因為附加率取 0.20 或 0.22。
> **系統做法**：附加率由 `SystemParameter` 依職類設定，計算結果一致可稽核。

**為何重要**（手冊 10.10）：每浪費技工 1 小時（等待、找料、無效會議），
公司損失 412 元而不是 240 元。**所有改善效益試算都必須用真實時薪。**

**實作位置**：`core/services/cost.py::true_hourly_rate(employee, at_date)`
P4 之前用職類預設值，P4 有薪資資料後改用實際月薪。

### 5.2 製造費用率與完全成本（手冊 13.1、13.3）

```
製造費用率 = 年度製造費用池 ÷ 年度直接人工工時
           = 34,310,000 ÷ 32,000 = NT$ 1,072/工時

製造成本 = 直接材料 + 直接人工 + (直接人工工時 × 製造費用率)
完全成本 = 製造成本 + 交付成本 + 管銷費用分攤
售  價  = 完全成本 ÷ (1 − 目標毛利率)
```

> ⚠️ **關鍵觀念**（手冊 13.3）：製造費用率（1,072 元）**高於**直接人工時薪（410 元）。
> 這代表設備與廠房攤提比人工更貴——所以提升 OEE 攤平固定成本至關重要。

**完整核算範例**（手冊 13.4，鋼構支架 100 件）

| 成本項目 | 金額 | 占比 |
|---|---:|---:|
| 直接材料（含 8% 損耗） | 33,588 | 35.0% |
| 直接人工（34 工時） | 13,848 | 14.4% |
| **製造費用（34h × 1,072）** | **36,448** | **38.0%** |
| 交付成本（包裝＋運輸） | 3,600 | 3.8% |
| 管銷費用分攤（10.2%） | 8,556 | 8.9% |
| **完全成本** | **96,040** | 100% |
| 單位成本 | 960 元/件 | |
| 售價（目標毛利 25%） | 128,053 | |
| 單價 | 1,281 元/件 | |

**三大核算陷阱**（手冊 13.5）——系統要主動防範：

| 陷阱 | 後果 | 系統防範 |
|---|---|---|
| 只算直接成本 | 漏算製造費用（占 38%），賠錢接單 | **報價畫面強制顯示五層成本堆疊**，缺一層就出警告 |
| 費用率不更新 | 沿用舊費用率導致失真 | `SystemParameter` 帶生效日；**費用率超過 12 個月未更新時在報價畫面警告** |
| 用材料額分攤 | 高材料訂單被高估 | 系統只提供「工時」與「機時」兩種分攤基礎 |

> ✗ **最致命錯誤**（手冊 13.5）：用「材料 + 人工 × 簡單加成」報價。
> 本例若漏算製造費用，成本會從 960 元低估為 600 元，看似毛利 30%，實際是虧損。

### 5.3 標準成本與差異分析（手冊第 15 章）

```
成本差異 = 實際成本 − 標準成本

材料差異 = 價格差異 + 用量差異
  價格差異 = (實際單價 − 標準單價) × 實際用量
  用量差異 = (實際用量 − 標準用量) × 標準單價

人工差異 = 工資差異 + 效率差異
  工資差異 = (實際時薪 − 標準時薪) × 實際工時
  效率差異 = (實際工時 − 標準工時) × 標準時薪
```

**範例拆解**（手冊 15.3）

| 差異來源 | 金額 | 可控性 | 行動 |
|---|---:|---|---|
| 材料價格上漲 | +2,000 | **外部** | 反映在未來報價或議價 |
| 材料損耗偏高 | +612 | 內部 | 檢討套料 |
| 人工效率偏低 | +1,452 | **內部（最大可控項）** | 查 OEE／換線 |
| 少量加班津貼 | +200 | 內部 | 排程改善 |
| **合計超支** | **+4,264** | | 可控部分 2,064（48%） |

**系統呈現要求**：差異分析畫面必須**明確標示「可控」與「外部」**，
否則管理者會把力氣花在無法改變的鋼價上。

### 5.4 停工成本（附錄 B 一）

```
停工成本 = 人工成本 + 固定成本
  人工成本 = 停工時數 × 影響人數 × 真實時薪
  固定成本 = 停工時數 × (設備日折舊 + 固定日費用) ÷ 8
```

**隱性成本的震撼範例**（手冊 6.5，設備故障停機 4 小時）

| 成本項目 | 金額 | 可見度 |
|---|---:|---|
| 維修人工 + 零件 | 8,000 | 顯性（帳面可見） |
| 停機 4h 人員閒置（10 人 × 432） | 17,280 | 半顯性 |
| 設備閒置折舊攤提 | 4,000 | 半顯性 |
| 產出損失（OEE 缺口） | 20,000 | **隱性** |
| 交期延誤風險（趕工／罰款） | 15,000 | **隱性** |
| **合計真實成本** | **64,280** | **顯性僅占 12%！** |

> ⚠️ 帳面成本只有 8,000，真實總成本 64,280——**隱性是顯性的 7 倍**。
> 若只盯著維修費省錢，就完全錯過真正的成本黑洞。

### 5.5 庫存資金占用（附錄 B 七）

```
年度資金占用成本 = 平均庫存值 × 資金成本率
                = 25,000,000 × 3.5% = NT$ 875,000/年
```

> ✗ **這 87.5 萬從不出現在損益表，卻是真實流失的資金。**（手冊 8.3）

### 5.6 供應商五維度評分（附錄 B 八）

```
加權原始分 = 交期×0.25 + 品質×0.30 + 財務×0.20 + 服務×0.15 + 價格×0.10
綜合評分   = 加權原始分 − 集中度扣分 + 備用加分
```

| 維度 | 權重 | 評分依據（系統自動抓取） |
|---|---:|---|
| **品質** | **30%** | 進料合格率（`InspectionRecord`） |
| **交期** | **25%** | 準時到料率（`PurchaseOrder` 承諾 vs 實到） |
| 財務 | 20% | 人工評分（財務狀況、信用） |
| 服務 | 15% | 人工評分（配合度、應變） |
| **價格** | **10%** | 相對市價 |

> 💡 **價格只占 10%**（手冊 7.6）。理由是那個經典範例：
> 供應商 A 單價便宜 2 元／kg（年省 20 萬），但不良率 3%、準時率 85%，
> 把隱性成本算進來後，**總成本反而比 B 貴 13 萬**。

### 5.7 EOQ 經濟訂購量（手冊 7.7）

```
EOQ = √(2 × 年需求 × 單次訂購成本 ÷ 單位年持有成本)

範例：D=12,000kg、S=1,500 元、H=6 元/kg
EOQ = √(2 × 12,000 × 1,500 ÷ 6) = √6,000,000 ≈ 2,449 kg/次
最佳訂購頻率 ≈ 每年 4.9 次
```

> 💡 **系統定位為「建議」而非「規則」**——實務上還要考慮供應商最小訂購量、
> 數量折扣、交期穩定性。系統顯示 EOQ 供採購參考，不強制。

---

### 5.8 目標成本法（手冊 27.4）

```
目標成本（容許成本）= 市場可接受價格 − 目標利潤
```

> 杜拉克第三大致命過失：**成本導向定價**（先算成本再加利潤）。
> 正解是**價格導向成本**——先看市場願付多少，再反推成本要壓到多少。

**系統支援**：報價畫面同時顯示兩個數字：
- 「依完全成本推算的售價」＝ 完全成本 ÷ (1 − 目標毛利率)
- 「依市價反推的容許成本」＝ 市場價格 × (1 − 目標毛利率)

兩者的差距就是**必須靠六階段改善補上的缺口**。

## 6. 六階段成本歸集模型

手冊第 5 章：**成本沿著「活動」流動，不是按「科目」記帳。**

| 成本階段 | 年度成本 | 占比 | 系統歸集來源（P2–P3） |
|---|---:|---:|---|
| ① 原物料採購 | 500 萬 | 6% | `PurchaseOrder` 金額 ＋ 採購人力成本（單數 × 3,780） |
| ② 入庫驗收 | 500 萬 | 6% | 倉儲分攤 ＋ 進料檢驗工時 ＋ **庫存資金占用**（隱性） |
| ③ 生產準備 | 505 萬 | 6% | 工程設計工時 ＋ **換線成本**（`ChangeoverLog`） ＋ 工裝攤提 |
| ④ **加工製造** | **3,331 萬** | **38%** | 直接人工（`WorkReport`） ＋ 設備運轉 ＋ **OEE 缺口**（隱性） |
| ⑤ 品質檢驗 | 998 萬 | 12% | `QualityCostEntry` 的 PAF 四類 |
| ⑥ 成品交付 | 1,149 萬 | 13% | `Shipment` 運費 ＋ 包裝 ＋ 交付失敗罰款 |
| 其他間接 | 1,700 萬 | 19% | 管銷費用 |

### 6.1 六大隱性成本追蹤表

手冊 6.3 診斷出的六項，合計逾 **1,200 萬／年**。系統的核心價值就是**讓它們現形**：

| # | 隱性成本 | 年估算 | 計算公式 | 資料來源 | 階段 |
|---|---|---:|---|---|:---:|
| 1 | 品質失敗成本 | ~462 萬 | 內部失敗 + 外部失敗 | `QualityCostEntry` | P3 |
| 2 | OEE 效率缺口 | ~210 萬 | (目標 OEE − 實際 OEE) × 理論產能價值 × 邊際貢獻率 | `OeeRecord` | P3 |
| 3 | 換線整備時間 | ~170 萬 | Σ(換線時數 × (真實時薪 + 設備閒置成本)) | `ChangeoverLog` | P3 |
| 4 | 交付失敗 | ~162 萬 | 延遲罰款 + 趕工加成 + 損壞賠償 | `Shipment`, `DeliveryReceipt` | P3 |
| 5 | 過度檢驗 | ~105 萬 | (未分級檢驗工時 − ABC 分級後應有工時) × 真實時薪 | `InspectionRecord` | P2 |
| 6 | 庫存資金占用 | ~101 萬 | 平均庫存值 × 資金成本率 | `StockLot`, `SystemParameter` | P2 |

> **手冊 6.4 的路徑：辨識 → 量化 → 追蹤 → 改善。**
> 系統負責前三步；第四步是人的工作。

## 7. KPI 快照表設計

### 7.1 `analytics_kpisnapshot`

不即時計算 KPI——**每日排程算好存起來**，前端只讀快照。理由：
即時聚合會掃全表，8GB 機器撐不住；且 KPI 本來就是趨勢指標，不需要秒級即時。

| 欄位 | 型別 | 說明 |
|---|---|---|
| `id` | BigAutoField | |
| `kpi_code` | varchar(40) | 如 `oee`、`inventory_turnover` |
| `period_type` | varchar(10) | `daily`／`monthly`／`yearly`／`rolling12m` |
| `period_start` / `period_end` | date | 統計區間 |
| `scope_type` | varchar(20) | `company`／`project`／`equipment`／`department`／`vendor` |
| `scope_id` | bigint NULL | 對應物件 id（`company` 時為 NULL） |
| `value` | numeric(18,6) | KPI 值 |
| `numerator` / `denominator` | numeric(18,6) | **分子分母也存**，方便下鑽與稽核 |
| `target_value` / `warning_value` | numeric(18,6) | 當時的目標與警示門檻 |
| `status` | varchar(10) | `good`／`warn`／`bad`／`nodata` |
| `computed_at` | timestamptz | |
| `note` | varchar(200) | 如「本期無排產，不計入」 |

**約束**：`UNIQUE(kpi_code, period_type, period_start, scope_type, scope_id)`
**索引**：`(kpi_code, scope_type, scope_id, period_start DESC)`

> 💡 **存分子分母的價值**：使用者看到「OEE 58%」時可以點開看到
> 「可用率 72% × 效能 85% × 良率 95%」，知道問題出在可用率——而不是只看到一個數字乾瞪眼。

### 7.2 `status` 判定

```python
if denominator == 0:      status = 'nodata'    # 不是 bad！
elif 越大越好:
    good if value >= target else (bad if value < warning else 'warn')
else:  # 越小越好（如換線時間、不良率）
    good if value <= target else (bad if value > warning else 'warn')
```

> ⚠️ **「無資料」不等於「不好」**。沒有排產的設備 OEE 應顯示「無資料」而非 0%，
> 否則公司平均 OEE 會被錯誤拉低——這是手冊 3.4「衡量的陷阱」的直接體現。

## 9. 平衡計分卡（手冊 20.5）

避免只看單一面向而次佳化。KPI 儀表板依四構面分組呈現：

| 構面 | 核心問題 | 本系統 KPI |
|---|---|---|
| **財務** | 股東如何看我們？ | 資金收攏率、專案毛利率、六階段成本占比 |
| **顧客** | 顧客如何看我們？ | OTD 準時率、客訴率、進料合格率 |
| **內部流程** | 我們須擅長什麼？ | OEE、平均換線時間、庫存週轉率、平均階段停滯天數 |
| **學習成長** | 我們能否持續進步？ | 改善提案數、技能證照數、SOP 閱讀率（P4） |

> ⚠️ **手冊 20.4 的警告**：不要只衡量容易量化的。
> 若只看財務（砍成本），可能犧牲顧客（品質下降）或學習成長（不投資人才）。
