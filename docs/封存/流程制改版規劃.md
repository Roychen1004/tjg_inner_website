## 1. 依據：八點需求 × 四個確認

老闆八點需求（原文濃縮）：

1. 取消土建／鋼構之分，全部按流程文件的**五大階段＋各階段流程**追蹤
2. 建案時勾選該案適用的階段與流程；**順序不可變**；建案後可再編輯
3. 每個勾選的流程產生一張**追蹤單元**，有主要負責人（如繪圖師）**收到此任務**，由專案管理者分配、撰寫詳細內容

5. 每個單元都要有**預計起訖日**＋應收／應付的**詳細日期**→ 給業主甘特圖、給內部金流評估

7. 專案卡片直接呈現**甘特圖**，不用點開就看到是否符合規劃
8. 看板內新增**日曆式甘特頁**，可勾選要看哪些專案

## 2. 核心概念：流程目錄 → 專案勾選 → 追蹤單元

```mermaid
flowchart LR
    A[流程目錄<br>5 大階段 × 18 工作項<br>全域、順序固定] -->|建案時勾選| B[專案的流程清單]
    B -->|每個流程一張| C[追蹤單元<br>負責人/詳細內容/預計起訖<br>狀態:未開始→進行中→已完成]
    C -->|階段4可再開| D[構件批次<br>待加工→…→已安裝]
    D -->|自動彙總| C
```

- **流程目錄**＝流程文件第 4 節的 18 個工作項（1.1–5.4），含各項的工作內容說明、
  產出物清單、完成條件，做成主檔資料（Django Admin 維護，D26 慣例）。
  每項有全域序號——**順序在目錄定死，任何專案都不能重排**（需求 2）。
- 土建案、小案＝勾比較少的流程（例如只勾 1.2、2.1、2.3、4.5、5.3），
  不再有 unit_type／兩套模板。
- 順序是「邏輯與顯示順序」，**不是日期約束**——流程文件原則 6 允許個別工作
  提前或延後（基礎預埋常早於加工），預計日期允許重疊。

### 追蹤單元（TrackingUnit 改造）

| 欄位 | 說明 |
|---|---|
| 流程項 | FK 目錄，同專案同流程只有一張 |
| 負責人 | FK 使用者，指派時發站內通知「你收到任務」 |
| 詳細內容 | 專案管理者撰寫，負責人在我的任務頁看到 |
| 預計開始／結束日 | **必填**（甘特圖與金流靠它） |
| 實際開始／結束日 | 回報時記錄 |
| 狀態 | 未開始→進行中→已完成（負責人回報完成即完成，不做二次確認——要改再說） |
| 進度 | 完成數量／總數量 或 百分比；階段 4 由批次自動彙總 |
| 產出物 | 附件掛單元（現有機制），目錄上的產出物清單顯示為檢核參考 |

### 構件批次（C3）

- 批次管線七站：`待加工→加工中→加工完成→表處中→待出貨→已出貨→已安裝`
- 一張批次同時餵四個流程單元的進度：
  廠內加工＝過「加工完成」的批次比例；表面處理＝過「待出貨」；
  出貨運輸＝過「已出貨」；吊裝安裝＝「已安裝」。
- 不分批的小案不開批次，四個單元直接手填進度。
- 基礎預埋不走批次，是獨立單元，允許提前完成。

### 建案後編輯（需求 2）

- 可隨時加勾流程（補一張單元）。
- 移除：單元**未開始且沒有附件／應付款**才能刪；已有紀錄的改標「不適用」保留歷史。

## 3. 金流怎麼算（C2，需求 5、6）

```
應收（期別制，現有四狀態不變：未到→可請款→已請款→已收款）
  每期＝金額基準 × 比例
  金額基準＝合約額；未簽約案用「估價金額」（C4）
  新增兩欄：觸發流程（FK 單元）、預計收款日
    - 觸發單元完成 → 該期自動轉「可請款」＋通知會計（流程文件 6.1 金流軌）
    - 預計收款日未填時，預設＝觸發單元預計結束日＋客戶帳期

應付（三狀態不變：待計價→已核可→已付款）
  每筆新增：掛在哪個單元（FK，選填）＋預計付款日
  訂料採購的料單款、表處委外款、運輸款、分包款 → 各掛對應單元
  分包合約（承諾成本）維持現狀，計價單多一個單元歸屬

現金流預測（三級確定性，規則不變，來源擴充）
  確定＝已請款應收＋已核可應付
  很可能＝可請款應收＋待計價應付（有預計日）
  估計＝未到期別（含未簽約案的估價金額期別）
  未成交／暫停案 → 不進預測
```

金流頁（需求 6）：維持 應收／應付／現金流 三個子頁，全部加**專案篩選**；
新增「依專案小計」列——單一專案的應收合計、應付合計、淨額一眼看到。

## 4. 角色與分頁（C1）

| 角色 | 分頁 | 說明 |
|---|---|---|
| 經營者 | 總覽／專案／看板／金流／設定（＋我的任務） | 即專案管理者：建案、勾流程、指派、填日期 |
| 會計 | 同上（不含設定的主檔管理） | 收付款登錄照舊 |
| **員工（新）** | **我的任務**＋看板 | 看被指派的任務與詳細內容、回報進度與完成；**看不到任何金額**（沿用 view_money 機制，金額型附件一併擋） |
| 檢視 | 看板（唯讀） | 維持現狀，備用 |

**我的任務頁**（從 git 恢復舊 MyWork 骨架改造）：
列出我負責的單元，按預計開始日排序，逾期標紅；點開看詳細內容與附件，
按鈕：開始／回報進度／完成。

通知：被指派時、單元逾期時通知負責人；單元完成觸發期別可請款時通知會計與經營者。

## 5. 畫面規劃

### 5.1 新增專案（需求 2）

```
┌ 新增專案 ─────────────────────────────┐
│ 名稱／客戶／狀態(進行中/未成交…)        │
│ 估價金額＿＿＿  合約金額＿＿＿(未簽可空) │
│ 預計工期  起＿＿＿ 迄＿＿＿             │
│                                        │
│ 流程勾選（順序固定，預設全勾）           │
│ ▾ 1 需求釐清與估價                     │
│   ☑1.1需求訪談 ☑1.2估價放樣 ☑1.3估價繪圖│
│ ▾ 2 報價協商與簽約 …                   │
│ ▾ 3 深化設計與備料 …                   │
│ ▾ 4 加工與現場施工 …                   │
│ ▾ 5 驗收與收款結案 …                   │
│                                        │
│ 請款期別（簽約後可再補）30/40/30 模板    │
│ 合約 PDF／設計圖 上傳（現有，保留）      │
│                [建立]                  │
└────────────────────────────────────────┘
```

建立後進專案詳細頁的**排程表**：一張表格逐列填每個單元的
負責人／預計起訖／詳細內容（18 列日期塞進建案表單太重，拆到這裡填）。

### 5.2 專案詳細頁

上：迷你甘特（同卡片，放大版）。
中：流程清單，按目錄順序分五段，每列＝狀態燈、負責人、預計/實際起訖、掛的錢。
下：請款期別（現有）＋批次（階段 4 展開）＋附件。

### 5.3 專案卡片迷你甘特（需求 7）

卡片空間有限，**以大階段彙總成 5 條橫桿**（不畫 18 條），
桿長＝該階段最早預計開始～最晚預計結束，填色＝完成比例，紅＝有逾期單元：

```
┌ 固越企業總部 ─────────── 進行中 ┐
│ 估價 ████                       │
│ 簽約  ██                        │
│ 深化   ███░░        ⚠加工圖逾2天│
│ 施工      ░░░░░░░░              │
│ 驗收             ░░             │
│       ▲今天                     │
└─────────────────────────────────┘
```

### 5.4 追蹤看板（需求 4）＋日曆甘特（需求 8）

看板分頁內三個視圖：

1. **流程視圖**（預設）：選一個專案 → 欄＝該案勾選的流程（依序），卡＝單元
   （狀態燈／負責人／起訖）。不選專案時退為總表：列＝專案、欄＝五大階段。
2. **批次視圖**：階段 4 的傳統看板，欄＝七站，卡＝批次，拖進度用。
3. **日曆甘特**：月曆格式，單元的預計起訖畫成跨日橫條，顏色＝專案，
   可勾選要顯示哪些專案（需求 8）；點橫條開單元。支援列印（給業主的甘特圖
   先用瀏覽器列印輸出，正式報表版留待下一輪）。

```
◀ 2026年9月 ▶   ☑固越 ☑彰化食品 ☐南投橋樑
┌─一──二──三──四──五──六──日─┐
│ 1   2   3   4   5   6   7  │
│ ▓▓▓固越·施工圖▓▓▓          │
│     ░░彰化·訂料採購░░░░░░  │
│ 8   9  10  11  12  13  14  │
│ ▓固越·簽認   ░░彰化·加工░░ │
└────────────────────────────┘
```

### 5.5 總覽

需關注清單擴充：未指派負責人的進行中單元、逾期單元（含負責人名字）、
本週應完成、可請款逾 7 天（現有）。

## 7. 實作順序與驗證

| 批 | 內容 | 驗證 |
|---|---|---|
| 1 | 目錄主檔＋種子；Project 狀態/估價金額；建案勾流程→生單元；排程表；順序鎖 | verify.py：建案勾 N 流程得 N 單元、順序不可重排、未簽約案可建 |
| 2 | 員工角色＋我的任務＋指派通知＋回報完成 | 員工帳號看不到金額/金額附件；指派收到通知；完成回寫 |

| 4 | 期別掛觸發單元（自動可請款）＋應付掛單元＋金流頁專案篩選 | 單元完成→期別轉可請款；預測含估價案 |
| 5 | 卡片迷你甘特＋看板三視圖（流程/批次/日曆） | 響應式檢查、300 卡上限照舊 |

每批完成跑 ruff／tsc／verify.py，全綠才進下一批。全部完成後更新
員工手冊（＋員工角色一頁）、系統目的與範圍、決策紀錄 D37。

## 8. 這輪不做（要做先講）

- 給業主的正式甘特圖報表（PDF 排版）——先用日曆頁列印
- 售前「評估中」狀態與案源管理、保留款/保固、品質檢驗、勞安（流程文件 v2 預留）
- 單元完成的二次確認（PM 覆核）——先一步到位，出問題再加
- 文件版本軌的完整版本鏈——附件照現行掛法，檔名帶版本號即可
