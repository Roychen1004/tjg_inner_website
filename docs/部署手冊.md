# 部署手冊

> 鐵正綱工程 內部管理系統
> **在一台新電腦上把系統架起來。**
>
> 這份的每一步都在乾淨環境實際跑過一次，不是照著設定檔推測的。

---

## 0. 先確認你要架的是哪一種

| | 開發機 | 正式機 |
|---|---|---|
| 目的 | 改程式、測功能 | 給員工每天用 |
| 指令 | `docker compose up -d` | `docker compose -f docker-compose.yml up -d` |
| 差別 | 自動套用 `docker-compose.override.yml`：<br/>把宿主機原始碼掛進容器、gunicorn `--reload` | **必須用 `-f` 排除 override** |
| DEBUG | True | **False** |

> ⚠️ **正式機一定要加 `-f docker-compose.yml`。**
> 不加的話 `docker-compose.override.yml` 會自動生效，把宿主機的原始碼
> bind mount 進正式環境——改一個檔案就直接影響線上，而且映像裡的程式碼形同虛設。

底下的步驟以**正式機**為準。開發機把 `-f docker-compose.yml` 拿掉即可。

---

## 1. 安裝 Docker

### Ubuntu 24.04

```bash
sudo apt-get update
sudo apt-get install -y docker.io docker-compose-v2 docker-buildx
sudo usermod -aG docker $USER
newgrp docker          # 或登出再登入
```

> ⚠️ **套件名稱是 `docker-compose-v2`，不是 `docker-compose-plugin`。**
> 後者在 Ubuntu 24.04 的官方 repo 裡不存在，會出現
> `E: Unable to locate package docker-compose-plugin`。
> 少裝 `docker-buildx` 的話 `docker compose build` 會失敗。

### 確認

```bash
docker --version              # 需要 20.10+
docker compose version        # 需要 v2.x（注意是 compose 不是 compose-plugin）
docker buildx version
```

## 2. 取得程式碼

```bash
sudo mkdir -p /opt && cd /opt
git clone <你的 repo 網址> tjg-inner
cd tjg-inner
```

路徑不一定要 `/opt/tjg-inner`，但 `deploy/backup.sh` 與 `deploy/crontab.sample`
預設是這個路徑。放別的地方記得一起改。

---

## 3. 建立 `deploy/.env`

**這一步不能跳過。** `.env` 有密碼所以不進版控，clone 出來沒有這個檔案。

```bash
cp deploy/.env.sample deploy/.env
```

然後**一定要改這五項**：

### ① 產生新的 SECRET_KEY

```bash
docker run --rm python:3.12-slim python -c \
  "import secrets; print(secrets.token_urlsafe(50))"
```

把輸出貼到 `SECRET_KEY=`。

> ⚠️ `.env.sample` 裡那把是開發用的、已經進過版控。
> **正式機用它等於把 session 簽章金鑰公開。**

### ② 填四組密碼（範本裡是空的）

```ini
POSTGRES_PASSWORD=<資料庫密碼>
DJANGO_SUPERUSER_PASSWORD=<系統管理員密碼>
SEED_DEMO_PASSWORD=<測試帳號密碼，正式機可留空>
PGADMIN_DEFAULT_PASSWORD=<pgAdmin 密碼>
```

### ③ 切成正式模式

```ini
DJANGO_SETTINGS_MODULE=main.settings.production
DEBUG=False
```

> 範本預設是 `local` + `DEBUG=True`。`docker-compose.yml` 雖然會覆寫
> api 容器的 `DJANGO_SETTINGS_MODULE`，但 `DEBUG` 不會——留著 True
> 會在出錯時把完整 traceback 與設定值吐給瀏覽器。

### ④ 加上這台機器的區網 IP

員工要從別台電腦連進來，就必須加：

```bash
hostname -I | awk '{print $1}'      # 查本機 IP，例如 192.168.1.50
```

```ini
ALLOWED_HOSTS=localhost,127.0.0.1,192.168.1.50
CSRF_TRUSTED_ORIGINS=http://localhost:30080,http://192.168.1.50:30080
```

> ⚠️ **`CSRF_TRUSTED_ORIGINS` 漏掉 IP 的話**：頁面打得開、但
> **所有登入與送出都會失敗**（403 CSRF）。非標準埠必須連埠號一起寫。

### ⑤ 確認埠號沒被占用

```bash
ss -tlnp | grep -E '30080|30800|30432|30050'   # 沒輸出＝沒被占用
```

要換的話改 `deploy/.env` 的 `PORT_*` **以及** `docker-compose.yml` 的 `ports`，
兩邊要一致。

## 4. 建置並啟動

```bash
docker compose -f docker-compose.yml build      # 第一次約 3–5 分鐘
docker compose -f docker-compose.yml up -d
```

**啟動時 api 容器會自己做完這些**（`deploy/entrypoint.sh`）：

```
[entrypoint] 等待資料庫就緒…
[entrypoint] 資料庫已就緒（第 1 次嘗試）
[entrypoint] 收集靜態檔…          ← 沒這步 Django Admin 會沒有 CSS
[entrypoint] 靜態檔完成
[entrypoint] 套用 migration…      ← AUTO_MIGRATE=true，不必手動 migrate
[entrypoint] 啟動 gunicorn …
```

### 確認起來了

```bash
curl http://localhost:30080/api/v0.1/health
```

```json
{"status": "ok", "api_version": "v0.1", "django": "5.1.5",
 "database": {"connected": true}}
```

沒回應的話：

```bash
docker compose -f docker-compose.yml ps            # 看誰沒起來
docker compose -f docker-compose.yml logs api --tail=50
```

---

## 5. 載入主檔與帳號

```bash
docker compose -f docker-compose.yml exec api python manage.py seed_masters
docker compose -f docker-compose.yml exec api python manage.py seed_accounts
```

| 指令 | 建了什麼 | 冪等？ |
|---|---|---|
| `seed_masters` | **11 個角色群組、3 條階段流程、21 項系統參數** | ✔ 可重跑 |
| `seed_accounts` | 系統管理員 ＋ 10 個測試角色帳號 | ✔ 可重跑 |

> **`seed_masters` 不能跳過。** 沒有階段流程就建不了任何追蹤單元，
> 沒有角色群組就沒有人有權限。

### 要不要載示範資料

```bash
docker compose -f docker-compose.yml exec api python manage.py seed_demo
```

三個示範案子（固越／彰化／南投），涵蓋四種請款觸發方式。
**教育訓練很好用，正式機不要載。**

已經載了要清掉：

```bash
docker compose -f docker-compose.yml exec api python manage.py seed_demo --clear
# 只清不載：清完按 Ctrl+C，或直接刪除那三個專案
```

## 6. 驗收

```bash
# 三個服務都在跑
docker compose -f docker-compose.yml ps

# 四個網址都通
curl -o /dev/null -s -w "前端      %{http_code}\n" http://localhost:30080/
curl -o /dev/null -s -w "Admin     %{http_code}\n" http://localhost:30080/admin/
curl -o /dev/null -s -w "Swagger   %{http_code}\n" http://localhost:30080/api/v0.1/swagger
curl -o /dev/null -s -w "健康檢查  %{http_code}\n" http://localhost:30080/api/v0.1/health

# 記憶體（目標常駐 < 1.5GB）
docker stats --no-stream --format "table {{.Name}}\t{{.MemUsage}}"
```

預期（`/admin/` 回 302 是正常的，未登入會導向登入頁）：

```
前端      200
Admin     302
Swagger   200
健康檢查  200

NAME             MEM USAGE
tjg-inner-web-1  12.6MiB / 128MiB
tjg-inner-api-1  168MiB  / 1GiB
tjg-inner-db-1   58MiB   / 1GiB
```

最後**從另一台電腦**開 `http://<這台的IP>:30080`，用 `admin` 登入一次。
連不上就是防火牆：

```bash
sudo ufw allow 30080/tcp
```

## 7. 正式上線前必做

### ① 刪掉測試帳號

`seed_accounts` 建的 10 個測試角色帳號（`owner`／`pm`／`plant`…）密碼統一，
**正式環境留著等於後門**。

到 **設定 → 員工**，把它們改成「停用」，或建立真實員工帳號後刪除。

> 員工不提供刪除（他做過的操作都掛在名下），停用即可。

### ② 改掉系統管理員密碼

第一次登入時系統會強制要求。

### ③ 裝排程

```bash
crontab -e
# 貼上 deploy/crontab.sample 的內容，把 TJG 換成實際路徑
```

> ⚠️ **只有「備份」與「資源監控」兩條現在能用。**
> 其餘標著 P2／P3 的指令還沒實作，取消註解會每天在 log 裡噴
> `Unknown command`。`crontab.sample` 裡已經幫你註解掉了。

### ④ 測一次備份能不能還原

備份沒測過等於沒有備份。

```bash
./deploy/backup.sh                     # 產生 backups/db_YYYYMMDD_HHMM.dump
ls -lh backups/
```

還原（**會覆蓋現有資料，請在測試環境練習**）：

```bash
docker compose -f docker-compose.yml exec -T db \
  pg_restore -U tjg -d tjg --clean --if-exists < backups/db_20260803_0100.dump
```

## 8. 常見問題

### api 一直重啟

```bash
docker compose -f docker-compose.yml logs api --tail=50
```

| 訊息 | 原因與處理 |
|---|---|
| `PermissionError: '/app/logs/app.log'` | `logs/` 目錄的擁有者不是容器內的 uid 1000。<br/>`sudo chown -R 1000:1000 logs`。<br/>**系統會自動退回只輸出到 stdout，不會因此起不來**，但檔案日誌會沒有 |
| `ModuleNotFoundError: django_extensions` | `.env` 的 `DJANGO_SETTINGS_MODULE` 是 `local`，但映像是用 production 需求檔建的。改成 `main.settings.production` |
| `could not connect to server` | db 還沒 healthy。entrypoint 會等 60 秒，超過就是 db 真的有問題，看 `logs db` |

### 登入按了沒反應 / 403

`CSRF_TRUSTED_ORIGINS` 沒包含你正在用的網址（含埠號）。改完要：

```bash
docker compose -f docker-compose.yml up -d     # 不是 restart！
```

> ⚠️ **`docker compose restart` 不會重讀 `env_file`。** 必須 `up -d`。

### 改了程式碼但沒生效

正式機的映像是 `COPY` 進去的，改宿主機檔案不會影響容器：

```bash
docker compose -f docker-compose.yml build api
docker compose -f docker-compose.yml up -d
```

（開發機有 `docker-compose.override.yml` 的 bind mount ＋ `--reload`，改完存檔即生效。）

### Admin 沒有 CSS

`collectstatic` 沒跑成功。entrypoint 每次啟動都會跑，看 logs 有沒有報錯：

```bash
docker compose -f docker-compose.yml exec api python manage.py collectstatic --noinput
```

### 要看資料庫

```bash
make pgadmin              # 啟動 pgAdmin（多吃 300MB，用完記得關）
# → http://127.0.0.1:30050　連線資訊已預先設定好，不用手動輸入
make pgadmin-stop
```

pgAdmin **只綁 127.0.0.1**，區網其他電腦連不到，這是刻意的。

## 9. 一頁速查

```bash
# ── 新機器完整流程 ────────────────────────────────────────
sudo apt-get install -y docker.io docker-compose-v2 docker-buildx
sudo usermod -aG docker $USER && newgrp docker

git clone <repo> /opt/tjg-inner && cd /opt/tjg-inner
cp deploy/.env.sample deploy/.env
vi deploy/.env        # SECRET_KEY、四組密碼、production、DEBUG=False、本機 IP

docker compose -f docker-compose.yml build
docker compose -f docker-compose.yml up -d
docker compose -f docker-compose.yml exec api python manage.py seed_masters
docker compose -f docker-compose.yml exec api python manage.py seed_accounts

curl http://localhost:30080/api/v0.1/health
sudo ufw allow 30080/tcp

# ── 日常維運 ──────────────────────────────────────────────
make up / down / logs / stats
docker compose -f docker-compose.yml up -d        # 改 .env 後（不是 restart）
docker compose -f docker-compose.yml build api && \
  docker compose -f docker-compose.yml up -d      # 改程式碼後
./deploy/backup.sh                                # 手動備份
```

| 網址 | 用途 |
|---|---|
| `http://<IP>:30080` | 前端（員工用） |
| `http://<IP>:30080/admin/` | Django Admin（管理員） |
| `http://<IP>:30080/api/v0.1/swagger` | API 文件 |
| `http://127.0.0.1:30050` | pgAdmin（只限本機） |
